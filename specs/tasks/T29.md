# T29 · Store model responses and replay a run without calling the model

- **Model**: — (Claude Code writes it)
- **Tier**: normal
- **Depends on**: T07, T12, T27
- **Goal**: `llm_calls` keeps tokens and cost but not what the model returned, so a run cannot be replayed (pitfall 2.22; design review 11/17, item 5). Store the response, and add a replay client that answers a new run from a recorded one: an offline demo, a free regression test after code changes, and a way to compare against another provider later.
- **Design**: `02-design.md` §1 models, §7; decisions D46, D66, D89
- **Libraries**: none new

## Decisions (D89)
- Migration `0012_llm_call_response`: `llm_calls.response jsonb NULL`: `{"content": str | null, "tool_calls": [{"id", "name", "arguments"}], "finish_reason": str, "model": str}`. Provider-neutral (our `LLMResponse`), not the provider's raw JSON. Older rows stay NULL.
- `record_call` writes it for every call (agent, method B, LC).
- `cda.llm.replay.ReplayLLM`: built from a recorded run's calls; key = (`prompt_sha256`, `tools_sha256`) computed exactly as `make_fingerprint` does; several calls with the same key are answered in recorded order. `complete` returns the stored message, finish reason and usage (so tokens and cost match the recording; nothing is spent). A request with no recorded answer raises `ReplayMiss` (a `LLMBadRequest`), so the check ends `error` / `llm_rejected` and the miss is visible; `ReplayLLM.misses` counts them.
- `cda.runner.replay` CLI: `uv run python -m cda.runner.replay --run <id> [--embedder bge|hash]` creates a new run with the source run's pack, method, model, budget, check set, prompt hash, settings (T27) and selected checks, runs it with `ReplayLLM`, and prints the new run id, status, findings that differ from the source (check, source status → replay status) and the miss count. It refuses a source run with no stored responses (`no recorded responses`) or a different check set / prompt hash from the current code (`recorded with a different check set / prompts`).
- Replay is exact only while prompts, tool results and settings are unchanged; any change to them shows up as misses. That is the point of using it as a regression test.

## Failing tests to write first
1. `record_call` stores the response JSON; the Langfuse export still sends no quotes or prompts (existing test passes)
2. Scripted fake run (method A) → replay run gives the same statuses, evidence quotes, steps, tokens and cost, zero misses
3. Same for method B and LC
4. Change a unit's text after recording → the affected check ends `error` / `llm_rejected`, `misses > 0`, other checks still replay
5. Two identical requests are answered in recorded order
6. CLI refuses a run without responses and a run with a different prompt hash; prints the differences
