## Facts measured on 26 Oct with the real API (do not re-test against OpenAI)
- Both models: `responses.create` with `tools=[{"type": "function", "name", "description", "parameters", "strict": true}]`, `tool_choice` `"auto"`, `"required"` or `{"type": "function", "name": ...}`, `parallel_tool_calls=false`, `store=false` → output contains a `function_call` item (`call_id`, `name`, `arguments`).
- Both models **reject** `temperature` and `seed` (HTTP 400). Do not send them.
- `reasoning={"effort": ...}`: luna accepts `none`, `low`, `medium`; sol accepts `low`, `medium`, `high`, `xhigh`. Send the model's configured value when set.
- A stateless follow-up works when the input contains the earlier `function_call` item(s) followed by `{"type": "function_call_output", "call_id", "output"}`; reasoning items need not be passed back.
- Usage: `input_tokens`, `output_tokens`, `input_tokens_details.cached_tokens`, `output_tokens_details.reasoning_tokens`.

## Mapping
- Messages → `input` items, in order: `system` → `{"role": "system", "content"}`; `user` → `{"role": "user", "content"}`; `assistant` with text → `{"role": "assistant", "content"}`; each assistant `ToolCall` → `{"type": "function_call", "call_id": id, "name", "arguments"}` (canonical JSON arguments, as today); `tool` → `{"type": "function_call_output", "call_id": tool_call_id, "output": content}`.
- Tools: from `strict_tool_schema` (Chat format) to the flat Responses function format above.
- Response → `LLMResponse`: `message` = assistant `Message` whose `content` is the concatenated `output_text` of message items (or `None`) and whose `tool_calls` are the `function_call` items (`ToolCall(call_id, name, arguments)`); `finish_reason` = `"tool_calls"` if any function call, else the response `status` (`completed`, or `incomplete` with `incomplete_details.reason`, e.g. `max_output_tokens`); `usage` = `Usage(input_tokens, output_tokens, cached_tokens)` (reasoning tokens are part of `output_tokens` and are billed as output — cost code unchanged); `model` = response `model`; `system_fingerprint` = `None` (not provided by Responses).
- `max_output_tokens` → `max_output_tokens`. `store=False` always.
- `seed` stays in the `complete()` signature for interface compatibility but is not sent.
- Fingerprint (D66): `prompt_sha256` hashes the exact `input` items sent and `tools_sha256` the exact tool list sent; `RequestFingerprint.temperature` becomes `float | None` and is `None`; `seed` is recorded as `None`. Make `llm_calls.temperature` nullable (migration 0006, downgrade sets NULLs to 0 before restoring NOT NULL).
- Errors and retries unchanged (D20, D21): 401/403 → `LLMAuthError`; 429/5xx/timeouts/connection errors → tenacity backoff, max retries, then `LLMRetryExhausted`; other 4xx → `LLMBadRequest`; never include messages, keys or response bodies in exceptions or logs. Invalid function-call arguments are still detected by `parse_tool_call` / `ToolArgsError` as today.
