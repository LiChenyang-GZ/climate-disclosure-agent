## Decisions (D90)
- `config/models.yaml` entries get `provider: openai | gemini` (default `openai`, so existing entries are unchanged) and, for Gemini, `thinking_level` (`minimal | low | medium | high | xhigh`). `reasoning_effort` is OpenAI only, `thinking_level` Gemini only; mixing is a load error.
- New keys: `flash` = `gemini-3.8-flash` (`thinking_level: low`) and `lite` = `gemini-3.5-flash-lite` (`thinking_level: minimal`). Prices per 1M tokens, paid tier, checked 27 Nov 2026 on the Google pricing page: flash input 1.50 / cached 0.15 / output 7.50 (list price from 1 Jan 2027; the introductory price to 31 Dec 2026 is half, so costs recorded before then are an upper bound); lite 0.30 / 0.03 / 2.50. Thinking tokens are billed as output and count against `max_output_tokens`.
- `cda.llm.providers.make_llm(models)` returns a client that routes each call by `models[model_key].provider` to `OpenAIClient` or `GeminiClient`, creating each lazily. `runner/deps.py` and `eval/run_eval.py` use it instead of `OpenAIClient(models)`.
- `GeminiClient` (`cda.llm.gemini_client`) builds `genai.Client()` with no arguments, so the SDK reads its own environment (`GEMINI_API_KEY` / `GOOGLE_API_KEY` for the Gemini API, or `GOOGLE_GENAI_USE_VERTEXAI=true` + `GOOGLE_CLOUD_PROJECT` + `GOOGLE_CLOUD_LOCATION` with Application Default Credentials for Vertex AI). Keys never pass through our code. Both routes are supported because Google Cloud credits may only cover Vertex AI, not AI Studio prepay (to be confirmed by Christy).
- Request mapping: `system` messages → `system_instruction` (joined with a blank line); `user` → `Content(role="user")`; `assistant` → `Content(role="model")` with a text part when there is content and one `function_call` part per tool call (`id`, `name`, `args` = parsed arguments); `tool` → `Content(role="user")` with a `function_response` part carrying the call's `id` and `name` (looked up from the assistant call) and `response` = the JSON object when the content is one, else `{"result": content}`; consecutive tool messages share one content. Tools → `FunctionDeclaration(name, description, parameters_json_schema=<the strict schema's parameters>)`. `tool_choice`: `auto` → mode `AUTO`; `required` → `ANY`; a tool name → `ANY` with `allowed_function_names=[name]`. Automatic function calling is disabled. `max_output_tokens` and `thinking_config(thinking_level=…)` from the model entry; no temperature or seed (as D78).
- Thought signatures: Gemini 3+ returns a `thought_signature` on the first function-call part of each step and rejects a later request without it (HTTP 400). `ToolCall` gets an optional `signature` (base64 of the bytes), set by `GeminiClient` and sent back on the same part. It is excluded from the request fingerprint and from `llm_calls.response` (D89 stays provider-neutral). A tool call in history without a signature (replayed run, older checkpoint) is sent with Google's documented placeholder `skip_thought_signature_validator`.
- Like `parallel_tool_calls=False` on OpenAI, only the first function call of a response is kept; the worker already uses only `tool_calls[0]`.
- Response mapping: tool calls from `function_call` parts; text from non-thought text parts; usage = `prompt_token_count` (in), `candidates_token_count + thoughts_token_count` (out), `cached_content_token_count` (cached); `model` = `model_version` or the configured name; finish reason `tool_calls` when there is a call, else `STOP` → `completed`, `MAX_TOKENS` → `max_output_tokens`, others lower-cased.
- Errors: HTTP 401, 402 (prepay balance exhausted) and 403 → `LLMAuthError` (fail fast, as D21); 429, 5xx, timeouts and connection errors → retried with the same bounded backoff as OpenAI, honouring `Retry-After`, then `LLMRetryExhausted`; other 4xx → `LLMBadRequest(status=…)`. No SDK exception is chained into ours.
- Key check: `Settings` gets presence-only fields for the Gemini key and Vertex settings; `Settings.llm_ready_for(provider)` replaces `llm_ready` in `POST /runs` and MCP `start_check`, checked against the requested model's provider. The error code stays `llm_key_missing`; the message names the provider. The `llm_auth` message no longer says "OpenAI".

## Failing tests to write first
1. Request mapping — system + user + assistant tool call + tool result + a second turn → the `contents`, `system_instruction`, tools and tool config sent match the rules above; function responses carry the call id and name
2. A response with text, a thought part and two function calls → one `ToolCall` (the first), its signature kept, thought text dropped, usage and finish reason mapped
3. The signature from step 1 is sent back on the next request's function-call part; a call without one gets the placeholder
4. `tool_choice` `auto` / `required` / named → modes `AUTO` / `ANY` / `ANY` + allowed name
5. Errors — 401, 402, 403 → `LLMAuthError` without retry; 429 and 503 retried then `LLMRetryExhausted`; 400 → `LLMBadRequest`; the SDK error is not chained
6. The fingerprint and `response_payload` of a Gemini response contain no signature and equal those of the same OpenAI-shaped response
7. `make_llm` routes by provider and builds each client once; a model table mixing `reasoning_effort` into a Gemini entry fails to load
8. `POST /runs` with a Gemini model and only an OpenAI key → 409 `llm_key_missing` naming Gemini; with a Gemini key → 201; the same for MCP `start_check`
