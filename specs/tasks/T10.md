# T10 · Quote verifier

- **Model**: sol
- **Tier**: strict
- **Depends on**: T08 (and T09, already merged)
- **Goal**: Code, not the model, decides whether each piece of evidence is real: the quote must appear verbatim (after whitespace normalisation) in the cited unit, or start in it and continue into the next unit, and the unit must belong to the run's pack and be visible to the user.
- **Design**: `02-design.md` §5 (Reading order), §7 (Verification); decisions D17, D28, D29, D61, D75
- **Libraries**: standard library for matching; sqlalchemy for the unit lookup (no new packages)

## Matching (`verify/quotes.py`, pure functions)
- `normalise(text) -> str`: every run of Unicode whitespace (`str.split()` semantics, so NBSP, tabs and newlines included) becomes one space; strip. Nothing else changes: case, punctuation, digits and typographic quotes/dashes must match exactly (D17 is "verbatim").
- `clean_quote(quote) -> str`: `normalise`, then remove **one** pair of wrapping quotation marks if the whole quote is wrapped in `"…"`, `“…”` or `'…'`, then remove a leading and/or trailing ellipsis (`...` or `…`) and the whitespace next to it. An ellipsis **inside** the quote is kept, so a quote that skips text fails.
- `match_quote(quote, unit_text, next_text=None) -> Match(ok: bool, reason: str, spans_next: bool)` on the cleaned quote:
  - empty after cleaning → `ok=False, reason="empty"`;
  - fewer than 8 characters after cleaning → `reason="too_short"` (a 1–2 word quote proves nothing);
  - contained in `normalise(unit_text)` → `ok=True, reason="ok", spans_next=False`;
  - otherwise, if `next_text` is given: join `normalise(unit_text)` and `normalise(next_text)` with one space — or with no space when the unit text ends with `-` (a word hyphenated across a page break). The quote is accepted (`spans_next=True`) only if it occurs in the joined text **starting inside the cited unit and ending inside the next unit** (a quote lying wholly in the next unit is not accepted for the cited unit);
  - otherwise `reason="quote_not_found"`.

## Database check (`verify/evidence.py`)
`async verify_evidence(conn, *, user_id, pack_id, items: Sequence[EvidenceItem], timeout_s=10.0) -> list[EvidenceCheck]`
- `EvidenceItem(unit_id: UUID, quote: str, role: "supports"|"side_a"|"side_b")`; `EvidenceCheck(unit_id, quote, role, ok, reason, spans_next, pdf_page, document_id)` in the same order as `items` (`pdf_page` / `document_id` None when the unit is not found).
- Runs inside `cda.tools.rls.tool_scope(conn, user_id, timeout_s)` (RLS, D61) **and** filters with the T08 team join and `documents.deleted_at IS NULL` (D29); the unit's document must be in `pack_id`. A unit that does not exist, is in another pack, is soft-deleted or is not visible → `reason="unit_not_found"` (one reason for all, no existence leak).
- "Next unit" = the unit in the same document with the smallest `seq` greater than the cited unit's, among `paragraph` and `table_row` units (D75). It must pass the same visibility rules.
- At most two SQL round trips for any number of items (one for the cited units, one for their next units); duplicates in `items` are allowed and each gets its own result.
- Never raises for a bad quote or an invisible unit; only database errors propagate.
- Writes nothing (T11 stores `evidence.verified`).

## Failing tests to write first (strict: every case its own test, seen failing first)
Matching (no Docker):
1. Exact substring → ok, `spans_next=False`
2. Differences only in whitespace (double spaces, newline, tab, NBSP) → ok
3. One changed character (case, digit, `,` vs `.`, `’` vs `'`, `–` vs `-`) → `quote_not_found`, each its own parametrised case
4. Quote wrapped in `"…"` / `“…”` / `'…'` → ok; quote with only an opening `"` → still compared with the `"` (fails if the text has none)
5. Leading / trailing `...` and `…` → stripped, ok; internal `...` joining two separate sentences → `quote_not_found`
6. Empty / whitespace-only / only-ellipsis quote → `empty`; 7-character quote → `too_short`; 8-character quote that matches → ok
7. Quote starting in the cited unit and ending in the next → ok, `spans_next=True`
8. Quote wholly inside the next unit → `quote_not_found`
9. Cited unit ending `climate-`, next starting `related disclosures` → quote `climate-related disclosures` ok
10. No `next_text` and the quote runs past the end of the unit → `quote_not_found`

Database (`db`, using a fixture like T08's: teams A/B, sarah/alex, two team-A packs, a soft-deleted document, units with `seq`):
11. Valid evidence on a team-A unit for sarah → ok with the unit's `pdf_page` and `document_id`
12. Same unit checked by alex → `unit_not_found`; random uuid → `unit_not_found`; unit of the other team-A pack → `unit_not_found`; unit of the soft-deleted document → `unit_not_found` — all with identical results apart from ids
13. Page-spanning quote: the next unit by `seq` is a paragraph on the next page → ok, `spans_next=True`; a `section` unit sits between them in `seq` → it is skipped
14. The next unit belongs to a different document (the cited unit is the last in its document) → no join; spanning quote → `quote_not_found`
15. Results keep input order; duplicates each get a result; 50 items → exactly 2 SQL statements are executed inside the scope (count with a `before_cursor_execute` listener, excluding the scope's own `SET`/`set_config`/savepoint statements)
16. With the T08 permission clause monkeypatched to always true, alex's check of sarah's unit is still `unit_not_found` (RLS layer)
17. After `verify_evidence` returns, `current_user` and `cda.user_id` on the connection are restored
