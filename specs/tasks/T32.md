## Changes
1. **Compare keeps `proposed_status` (D88)**: when the inconsistency step (`compare/inconsistencies.py`) moves a finding to `needs_review` from a status the model can submit (`evidence_found`, `partial_evidence`, `no_evidence_found`, `inconsistent`) and `proposed_status` is empty, it stores the old status as `proposed_status`. A finding whose `proposed_status` is already set keeps it.
2. **`run_eval --keep-tool-results N`** (default the `RunDeps` default, at least 1), passed to `RunDeps` and so recorded in `runs.settings`; recorded in `results.json` next to `step_cap` and `token_cap`.
3. **Runs created through the API or MCP record their settings when queued (D87)**: `create_run` writes `RunSettings.defaults()` (the `RunDeps` defaults) into `runs.settings`, so a queued run already says what it will run with. The worker still validates stored settings as before.
4. **Tool events name the units they returned**: `tool_called` events add `unit_ids` (search hits in rank order, or the unit read by `read_unit`), so "where did the results land" (note 13, item 17) can be measured from stored runs. Payload only; no tool result changes.
