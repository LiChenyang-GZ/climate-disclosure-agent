## Types (`types.py`)
Plain frozen dataclasses / Pydantic models, no OpenAI types leak out of `openai_client.py`:
- `Message(role: "system"|"user"|"assistant"|"tool", content: str | None, tool_calls: list[ToolCall] = [], tool_call_id: str | None = None)`
- `ToolCall(id: str, name: str, arguments: str)` (raw JSON text as returned)
- `ToolSpec(name: str, description: str, args_model: type[BaseModel])`
- `Usage(tokens_in: int, tokens_out: int, tokens_cached: int)` (`tokens_in` includes cached)
- `LLMResponse(message: Message, finish_reason: str, usage: Usage, model: str, system_fingerprint: str | None, latency_ms: int, fingerprint: RequestFingerprint)`
- Errors (all subclass `LLMError`): `LLMAuthError` (401/403, never retried, D21), `LLMRetryExhausted` (after the last retry, carries the last status/kind), `LLMBadRequest` (400/404/422, not retried), `ToolArgsError` (see below).

## `client.py`
`LLMClient` Protocol: `async def complete(self, *, messages: list[Message], tools: list[ToolSpec], model_key: str, seed: int | None = None, tool_choice: "auto" | "required" | str = "auto", max_output_tokens: int = 2000) -> LLMResponse`. A `str` other than `auto`/`required` forces that tool name. Temperature is always 0 (D18) and not a parameter.

`parse_tool_call(call: ToolCall, tools: list[ToolSpec]) -> BaseModel`: unknown tool name or invalid JSON or Pydantic validation failure → `ToolArgsError(tool_name, message)` where `message` is a short, model-readable explanation (the Pydantic error list without input values, ≤ 1,000 chars). The one-retry rule (D47) lives in the worker (T11); this function only validates.

## `schema.py` — strict function schemas (D47)
`strict_tool_schema(spec: ToolSpec) -> dict` returns `{"type": "function", "function": {"name", "description", "parameters", "strict": True}}` where `parameters` is the args model's JSON schema made OpenAI-strict: every object has `additionalProperties: false` and lists **all** its properties in `required` (optional fields become nullable via `anyOf [..., {"type": "null"}]`, which Pydantic already emits for `X | None`); `title` and `default` keys removed; `$defs` kept and references left as `$ref`. Raise `ValueError` for a model field with a default but not nullable (strict mode cannot express "optional and non-null"), so mistakes are caught at import time in T08/T11.

## `openai_client.py`
`OpenAIClient(models: ModelTable, *, timeout_s=60.0, max_retries=3, sleep=asyncio.sleep, http_client: httpx.AsyncClient | None = None)`.
- Uses `openai.AsyncOpenAI(max_retries=0, timeout=timeout_s, http_client=http_client)` (our retry is the only retry). The API key comes from the SDK's own environment lookup; this code never reads, logs or stores it.
- Request: Chat Completions, `model` from the model table, `temperature=0`, `seed`, `tools=[strict_tool_schema(...)]` (omitted when `tools` is empty), `tool_choice` mapped to the SDK form, `parallel_tool_calls=False` when tools are given, `max_completion_tokens=max_output_tokens`. Messages keep their order (shared system prompt first, D27).
- Response: first choice → `Message` (content and tool calls), `finish_reason`, usage (`prompt_tokens`, `completion_tokens`, `prompt_tokens_details.cached_tokens` or 0), `system_fingerprint` (D48), `latency_ms` measured around the call including retries.
- Errors (D20, D21): `AuthenticationError` / `PermissionDeniedError` → `LLMAuthError` immediately. `RateLimitError`, `APITimeoutError`, `APIConnectionError`, `InternalServerError` (5xx) → retry with exponential backoff (1 s, 2 s, 4 s, plus up to 0.25 s jitter; honour a `Retry-After` header up to 30 s) for at most `max_retries` retries, then `LLMRetryExhausted`. Other `BadRequestError`-type errors → `LLMBadRequest`. Use `tenacity` with the injected `sleep` so tests do not wait.
- Error messages never contain the request body, headers or API key.

## `fingerprint.py` (D66)
`RequestFingerprint(model: str, prompt_sha256: str, tools_sha256: str, temperature: float, seed: int | None)`. `prompt_sha256` = SHA-256 of canonical JSON (`sort_keys=True, separators=(",", ":")`, UTF-8) of the messages as sent; `tools_sha256` of the list of strict tool schemas (empty list when no tools). Same inputs → same hashes; any change in a message, tool schema, model or seed changes the fingerprint.

## `cost.py` (D22)
- `ModelTable.load(path="config/models.yaml")`: Pydantic-validated `{key: ModelPrice(model, input, cached_input, output)}` (USD per 1M tokens); unknown `model_key` → `KeyError` naming the key.
- `cost_usd(price, usage) -> Decimal` = `((tokens_in - tokens_cached) * input + tokens_cached * cached_input + tokens_out * output) / 1_000_000`, quantised to 6 decimal places (matches `numeric(12,6)`).
- `estimate_tokens(messages, tools) -> int` = `ceil(total characters of message contents, tool-call arguments and tool schemas JSON / 4) + 4 * len(messages)` (no tokenizer dependency).
- `max_cost_usd(price, *, prompt_tokens, max_output_tokens) -> Decimal`: the pessimistic cost used for budget pre-deduction (no cache discount).

## `calls.py`
`async record_call(conn, *, run_id, check_id, step, response, cost) -> None`: inserts one `llm_calls` row from the response and its fingerprint (`model`, `prompt_sha256`, `tools_sha256`, `temperature`, `seed`, `system_fingerprint`, token counts, `cost_usd`, `latency_ms`). Nothing else writes `llm_calls`.

## `fake.py`
`FakeLLM(script: list[FakeTurn | Exception])` implementing `LLMClient` with no network:
- `FakeTurn(content: str | None = None, tool_calls: list[tuple[str, dict | str]] = [], usage: Usage = Usage(100, 20, 0), finish_reason = "stop" | "tool_calls" by default)`; dict arguments are JSON-encoded; a `str` is passed through raw (to script invalid JSON). Tool call ids are `call_1`, `call_2`, … in order.
- Each `complete` call consumes the next item; an `Exception` item is raised instead (to script `LLMAuthError`, `LLMRetryExhausted`, …). Calling past the end raises `AssertionError("FakeLLM script exhausted")`.
- `.requests` records every call's `messages`, `tools`, `model_key`, `seed`, `tool_choice` for assertions. Responses carry a real `RequestFingerprint` computed the same way as the OpenAI client, `model` = the model table name if a table is given, else the key, `system_fingerprint="fake"`, `latency_ms=0`.

## Failing tests to write first
No test touches the network: the OpenAI client is tested through `httpx.MockTransport` returning canned Chat Completions JSON / error responses.
1. `strict_tool_schema` on a model with a nested list of objects and an `X | None` field → every object has `additionalProperties: false`, all properties required, nullable union kept, no `title`/`default`; a field with a non-null default → `ValueError`
2. `parse_tool_call`: valid → model instance; unknown tool → `ToolArgsError`; invalid JSON → `ToolArgsError`; wrong type → `ToolArgsError` whose message names the field and does not contain the input value
3. OpenAI client builds the request: model name from the table, `temperature 0`, `seed`, strict tools, `parallel_tool_calls false`, `tool_choice` for `auto`, `required` and a forced tool name; no `tools` key when there are no tools
4. Response mapping: text reply; tool-call reply; usage with and without `cached_tokens`; `system_fingerprint`
5. 429 twice then 200 → succeeds after 2 sleeps of increasing length; `Retry-After: 7` → that sleep is 7 s; 500 four times → `LLMRetryExhausted` after exactly 3 sleeps; timeout → retried
6. 401 → `LLMAuthError` with zero sleeps and exactly one HTTP request; 403 → same; 400 → `LLMBadRequest`, not retried
7. Error text never contains the Authorization header value or the request body
8. Fingerprint: identical inputs → identical hashes; changing one message character, a tool schema, the model or the seed changes it; key order in a dict argument does not
9. `cost_usd` matches a hand calculation for `sol` with cached tokens; quantised to 6 dp; `max_cost_usd` ≥ `cost_usd` for the same tokens; unknown model key → `KeyError`
10. `estimate_tokens` matches the formula
11. `FakeLLM`: scripted tool calls come back with `call_1`, `call_2` ids and the right arguments; a scripted exception is raised at its turn; exhaustion → `AssertionError`; `.requests` records inputs
12. (db) `record_call` inserts one `llm_calls` row with all fingerprint, token, cost and latency fields
