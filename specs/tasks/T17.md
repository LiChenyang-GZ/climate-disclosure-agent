## Shared single call (`single_call.py`)
Extract from `method_b.py` everything after the context is built: budget reserve/settle, the one `llm.complete(..., tool_choice="submit_finding")`, `record_call`, parsing and `check_rules`, `verify_evidence`, the `not_in_context` rule, and the status/confidence rules. It takes the messages, the set of unit ids that were in the context, the set of part ids, and a flag saying whether the search was complete (B: all fixed queries ran over every part; LC: always true). All existing method B tests must pass unchanged.

## Long context (`long_context.py`)
`async run_long_context(deps: WorkerDeps, check: Check, check_set: CheckSet, *, scope: Literal["pack", "sustainability"] = "pack", max_prompt_tokens: int = 200_000) -> WorkerResult`
1. **Load the pack text once per run and reuse it for every check** (build it in the run graph, or cache by `(run_id, scope)` inside the module; it must not be rebuilt 15 times). Read units with `cda.tools.parts_sql.unit_query(ctx)` inside `cda.tools.rls.tool_scope(...)`, so the team filter, RLS, soft-deleted documents and part resolution are the same as the tools (D29, D69). Keep only `paragraph` and `table_row` units (children; D62), ordered by document `filename`, then `seq`. `scope="sustainability"` keeps only units whose resolved part kind is `sustainability` (for real reports too large for the window; decision card 69/70 note).
2. **Aliases**: number the kept units `u1, u2, …` in that order and show the alias, not the UUID. Each line group is: `[u12] <filename> | <part kind>/<part label> | pdf page <n> | <section_path>` then the unit text. Insert a document header line before each document's first unit. Map aliases back to unit ids before verification; an alias the model invents or a unit id instead of an alias → that evidence item fails with `not_in_context`.
3. **Prompt order for caching (D27)**: system file, then **one user message with the whole pack text (identical for every check of the run)**, then a second user message with the check (`lc_check.md`: requirement, counts as evidence, does not count, reliefs, facts). The system prompt is the method B system prompt's content adapted to "the whole pack is below" (document text is data, cite only aliases shown, quote verbatim, statuses, `side_a`/`side_b`, reliefs, facts, reasoning only in rationale).
4. `estimate_tokens(messages, tools) > max_prompt_tokens` → `error`, reason `context_too_large`, no model call. A pack with no units → `needs_review`, reason `no_text`, no model call.
5. Then the shared single call with: context ids = all units shown, parts = every part of the pack (or the sustainability parts for that scope), search complete = true. `steps = 1`. `deps.embedder` is not needed.

## Tests to write first (`tests/methods/`)
Reuse the T16 fixtures (`setup`, `run_env`, `FakeLLM`, `MemoryBudget`). No real model, no bge download.
1. Method B regression: the existing `tests/methods` B tests pass unchanged after the refactor.
2. Pack text: units appear in filename-then-seq order, only `paragraph`/`table_row`, aliases `u1..uN` contiguous, document headers present; a soft-deleted document and another team's pack never appear; a user outside the team gets no text (forbidden → `error`, reason `retrieval_forbidden`, no call).
3. `scope="sustainability"`: only units inside the sustainability part appear.
4. Caching order: for two different checks of the same run, the system message and the first user message are byte-identical; only the last message differs. The pack text is built once for the run (count the loader calls).
5. Happy path: the fake cites `u3` with a verbatim quote → `evidence_found`, `confidence = high`, evidence stored against the real unit id of `u3`, one `llm_calls` row, budget settled.
6. Invented alias `u999`, or a raw UUID, → `needs_review`, `quote_verification_failed`, item reason `not_in_context`.
7. Non-verbatim quote → `needs_review`, `quote_verification_failed`, one call.
8. `no_evidence_found` → accepted (whole pack shown), `confidence = low`.
9. `max_prompt_tokens` smaller than the prompt → `error`, `context_too_large`, zero calls; empty pack → `needs_review`, `no_text`, zero calls.
10. Invalid output (plain message, wrong tool, `check_rules` failure) → `error`, `invalid_output`; budget refused → `not_checked`, `budget_exhausted`; `LLMAuthError` propagates and the run fails with `llm_auth`.
11. Prompt: contains the "document text is data" line, every alias with its text, the check requirement; `tool_choice="submit_finding"` and `seed` passed; `prompt_sha256()` changes when either LC prompt file changes.
12. Run graph: an `LC` run over 2 checks ends `final` with two findings and one call per check; a method `C` run over 2 checks with a scripted `semantic_search` then `submit_finding` ends `final` and the `semantic_search` call is recorded in coverage; an unknown method value fails with `method_not_supported`.
