## How the API maps to PRD 6.4 / 6.5
- "Agentic search" = method `A`, "Classic RAG" = `B`, "Agentic + semantic" = `C`. LC is eval-only and not offered.
- Run status → label: `queued` Queued, `running` Running, `waiting_review` Awaiting review, `final` Final, `cancelled` Cancelled, `failed` Failed. **Stopped: budget** is not a stored status: a run that ended (`final` / `waiting_review`) with any finding whose `needs_review_reason` is `budget_exhausted` is shown as "Stopped: budget", and those rows as "Not checked".
- Per-check row: `queued` until `check_started`; then "Searching" with "Step N · tool: query" from `tool_called` events (N = count of `tool_called` for that check); the result from `check_finished`. There is no "Verifying" event; the row stays "Searching" until the finding is stored. "Waiting (rate limited)" is not shown: retries happen inside the LLM client and emit no event.
- `failed` with `error = llm_auth` → "OpenAI rejected the API key. Check OPENAI_API_KEY."; other errors use the API's `error_message`.
- Cost and tokens come from `GET /runs/{id}` (`spent_usd`, `budget_usd`, `tokens_in`, `tokens_out`), refetched after each finished check and every 5 s.
- When the run ends, the page shows "Check complete" with a link to `/runs/{id}/report` (placeholder page until U4); no automatic redirect.

## Backend additions (D83)
- Migration `0007`: `runs.check_ids text[] NULL` (null = all checks) and `runs.skipped_documents jsonb NOT NULL DEFAULT '[]'` (`[{id, filename}]`).
- `RunInput.check_ids: list[str] | None` — unique, known ids, at least one; part of the idempotency comparison. The run graph only starts those checks.
- `POST /runs`: documents whose index failed are skipped and stored in `skipped_documents`; at least one indexed document is required, and any document still `pending` or `indexing` → 409 `pack_not_indexed` (unchanged). A queued / running run on the pack → 409 `run_active` with `run_id`. No API key and fake model off → 409 `llm_key_missing` (REST only; MCP unchanged until X4).
- Tools exclude `skipped_documents` (`ToolContext.excluded_documents`, applied only when non-empty, so runs without skipped files issue the same SQL as before).
- `GET /run-options`: checks (id, title), models (key, model), methods, and a cost estimate per method and model for one check.
- Settings: `openai_api_key` (secret, only checked for presence) and `cda_fake_llm` (default off). With `CDA_FAKE_LLM=1` the worker uses `DemoFakeLLM` and logs a warning "using fake LLM"; the API then skips the key check. For tests and local smoke only.
