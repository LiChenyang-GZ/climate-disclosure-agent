# T22 · MCP server

- **Model**: sol
- **Tier**: normal
- **Depends on**: T08/T09 (tools, permissions, RLS role), T20 (REST API) — merged
- **Goal**: A local stdio MCP server that lets an MCP client (Claude Desktop, Claude Code) list packs, read runs and findings, search a pack and start a check, through the **same Python functions and permission checks as the REST API** (D51). No review through MCP.

## Shared functions (`cda.api.service`)
The REST routes and the MCP tools call the same functions. Move the bodies, do not copy them. Each function takes an `AsyncConnection` and the actor `dict` (the `users` row) and raises `cda.api.errors.APIError` exactly as the routes do today (404 for anything not visible, 403 for role, 409/422 as now).
- `load_actor(conn, handle) -> dict`: the user lookup now inside `deps.identity`; unknown or not in `("sarah", "alex")` → `APIError(401, "unauthorized", …)`. `deps.identity` calls it.
- `list_packs(conn, actor)`, `get_run(conn, actor, run_id)`, `finding_rows(conn, actor, run_id)` (after `visible_run`), `finding_detail(conn, actor, finding_id)`, `create_run(conn, actor, body: RunInput, idempotency_key, index_state) -> tuple[dict, bool]` (bool = created; the route turns `False` into 200).
- Index status: `document_info` today reads `request.app.state` (`indexing`, `index_errors`, `document_states`). Replace that with a small `IndexState` dataclass holding those three collections; the app keeps one in `app.state.index_state` (keep the old attribute names working if tests use them, or update the tests that read them). The MCP server uses an empty `IndexState()`: it never indexes, so status comes from the database alone (`done` when every `paragraph`/`table_row` unit has an embedding and the document has context headers, as today).
- `wake(conn)` (`pg_notify('cda_runs', '')`) and `audit(...)` live where both can call them.
- After the move, every existing test in `tests/api/` passes unchanged.

## User identity
- The MCP server runs as **one demo user for the life of the process**, chosen by the environment variable `CDA_MCP_USER` (`sarah` or `alex`), set in the client's server entry (`env` block of `config/mcp-client.example.json`). It is **not** a tool argument, so the model cannot pick or switch users.
- At startup: missing or any other value → write one line to stderr (`CDA_MCP_USER must be sarah or alex`) and exit with code 2, before serving. Do not check the database at startup (it may not be up yet).
- On every tool call: open a connection, `load_actor(conn, handle)`, then call the shared function. A handle missing from the `users` table (seed not run) → tool error `unauthorized`.
- Database: `Settings().database_url` (env `DATABASE_URL`, as the API and worker). One engine per process, disposed on shutdown.

## Tools
All arguments are validated by pydantic (FastMCP type hints); UUIDs as strings. Results are JSON objects (structured content), with UUIDs, datetimes and Decimals as strings. Quotes are plain text (D50); never HTML or Markdown.
1. `list_packs()` → `{"packs": [...]}`: id, company, reporting_year, team name, document_count, as `GET /packs` (add team name only if cheap; otherwise team_id).
2. `get_run(run_id)` → the same object as `GET /runs/{id}` (status, method, model, budget, spent, tokens, timings, counts by status, `error` + `error_message`).
3. `get_findings(run_id, finding_id=None)` → without `finding_id`: `{"findings": [...]}` as `GET /runs/{id}/findings`; with `finding_id`: the object from `GET /findings/{id}` (rationale, evidence with plain-text quotes and pages, facts, inconsistencies, reviews, trace). A `finding_id` that belongs to another run → `not_found`.
4. `search_pack(pack_id, query, mode="keyword", limit=5)` → calls `cda.tools.registry.run_tool` with a `ToolContext(conn, actor id, pack id)` and `keyword_search` or `semantic_search` (D61: same `cda_tool` role and RLS as the agent). Returns the `ToolResult` as JSON (`ok`, `category`, `message`, `data`). `mode` ∈ `keyword|semantic`; `limit` 1–10. Semantic mode uses an embedder created lazily on first use (`BgeEmbedder`, loaded with `asyncio.to_thread`), injectable for tests (`build_server(embedder=..., engine=...)`). A pack the user cannot see → `not_found` (check `visible_pack` first, so it is never `forbidden` vs `not_found` depending on the tool).
5. `start_check(pack_id, method, model_key, idempotency_key, budget_usd=2.0)` → the shared `create_run` (same validation: method `A|B|C`, model key from `config/models.yaml`, 0 < budget ≤ 10, pack fully indexed, idempotency rules of D24). Returns `{"run": {...}, "created": true|false}`. Analyst and lead may both start checks on visible packs. The tool description tells the client to reuse the same `idempotency_key` when retrying the same request, and that the worker runs the check (poll `get_run`). The audit row records the action as today, with `detail` `{"via": "mcp"}`.

Tool annotations: the first four `readOnlyHint=True`; `start_check` `readOnlyHint=False`, `destructiveHint=False`, `idempotentHint=True`. Exactly these five tools are registered; no review, cancel, upload, index or export tool.

## Errors
- An `APIError` becomes an MCP tool error result (`isError: true`) whose text is the JSON `{"error": code, "message": message}` (plus the same extra fields the REST API returns, e.g. a current version). Pydantic argument errors → `{"error": "invalid_request", ...}` with only field names.
- Any other exception → `{"error": "internal_error", "message": "Request failed"}`; the exception is logged to stderr with its type only. No SQL, paths, stack traces or secrets reach the client.
- Nothing is ever written to stdout except MCP protocol messages (stdio transport). Logging goes to stderr.

7. Errors: a patched shared function raising `RuntimeError("SELECT secret FROM x at C:\\path")` → `internal_error`, and the result text contains neither `SELECT` nor `C:\`.
8. Stdio smoke test (no Docker needed): start `python -m cda.mcp_server` as a subprocess with `CDA_MCP_USER=sarah` using the SDK's stdio client, `initialize` and `list_tools` succeed, then the process exits cleanly when the client closes.

## Do not
- add a review, cancel, upload, index or export tool, or any tool not listed
- let the client choose or change the user per call
- write a second copy of the permission or run-creation logic for MCP
- run checks or indexing in the MCP process (the worker runs checks, D43)
- use HTTP/SSE transport, or call the REST API over HTTP from the MCP server
- change the run graph, worker, tools or methods
