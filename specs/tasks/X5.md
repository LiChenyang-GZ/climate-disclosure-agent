# X5 · Claude Code hooks for this repo

- **Model**: — (Claude Code writes it)
- **Tier**: normal
- **Depends on**: —
- **Goal**: turn the repo's written rules (CLAUDE.md, 2.6.1 of the handoff) into hooks that run on every Claude Code tool call in this repo, so a slip is stopped or flagged before it happens.
- **Libraries**: none (hook scripts use the standard library only, so they start fast with any Python ≥ 3.10)

## Hooks (`.claude/settings.json`, scripts in `.claude/hooks/`)
**PreToolUse `guard.py`** on `Edit|Write|MultiEdit|NotebookEdit|Bash|PowerShell`. Paths are judged relative to the project root; files outside the repo are not judged.
| Rule | Decision | Why |
|---|---|---|
| write to `.env` / `.env.*` (not `.env.example`) | deny | secrets stay out of tool calls (CLAUDE.md) |
| write under `data/real/` | deny | real-company PDFs and answer keys are never edited or committed (D72) |
| write to `uv.lock` or `web/package-lock.json` | deny | change dependencies with `uv add` / `npm install` |
| write to `src/cda/checks/checks.yaml`, `src/cda/agent/prompts/**`, `**/answer_key*.yaml`, `src/cda/eval/**` | ask | frozen until the note-12 / note-13 decisions (handoff 2.6.1) |
| shell command that reads `.env` (`cat`, `type`, `head`, `tail`, `less`, `more`, `grep`, `sed`, `awk`, `Get-Content`, `source`, `.`) | deny | same as above |
| `git commit`, `gh pr create/edit/comment`, `gh issue …` whose text contains `Co-Authored-By`, `Generated with Claude` or `🤖` | deny | no AI attribution in commits or PRs (CLAUDE.md) |
| `git push` with `--force`, `-f`, `--force-with-lease` | ask | force-push only with Christy's approval |
| `codex exec` with `--dangerously-bypass-approvals-and-sandbox` | deny | CLAUDE.md step 3 |
| `codex exec`, `run_eval` without `--dry-run` | ask | can spend OpenAI credits |
Everything else: no output, exit 0 (normal permission flow). Malformed input: exit 0 (never block on a hook bug).

**PostToolUse `post_edit.py`** on `Edit|Write|MultiEdit`: for a `.py` file inside the repo, run `uv run ruff format <file>` then `uv run ruff check --fix <file>`; if errors remain, return `decision: "block"` with ruff's output so Claude fixes them. Other files: nothing.

The rules are guardrails against slips, matched on text; they are not a security boundary (a command can be written to dodge them). Codex is not affected (hooks are Claude Code only).

## Files
- `.claude/settings.json`, `.claude/hooks/guard.py`, `.claude/hooks/post_edit.py`, `.gitignore` (`.claude/settings.local.json`)
- `tests/hooks/test_guard.py`, `tests/hooks/test_post_edit.py`

## Tests
1. Each rule above: one input that triggers it (deny / ask with a reason) and a near miss that does not (`.env.example`, `data/synthetic/…`, a normal `git push`, a commit message without attribution, `run_eval --dry-run`)
2. Paths outside the repo, Windows backslash paths and absolute paths resolve correctly
3. Malformed JSON or missing fields → exit 0, no output
4. The scripts run as a subprocess with stdin JSON and print the documented JSON contract
5. post_edit: a badly formatted Python file is formatted; a file with an unused import is fixed; an unfixable error returns `decision: block`; a non-Python file is ignored
6. `.claude/settings.json` is valid and every hook command points at an existing script

## Done when
- tests pass; ruff, ruff format, mypy, pytest; CI green
- a new Claude Code session in the repo shows the guard firing on a blocked path (manual check, noted in the PR)

## Do not
- block Christy's normal workflow: specs, notes outside the repo, `git push` without force, ordinary commits
