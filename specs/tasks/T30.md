# T30 · Shorten old tool results in the agent's history

- **Model**: — (Claude Code writes it)
- **Tier**: strict
- **Depends on**: T11, T27
- **Goal**: D15 and D59 say old tool results may be truncated; the code never did. Every step resends the full history, so token use grows faster each step and 13–53 % of agent checks hit the token cap (note 13, item 19; design review 11/17, item 2). Keep the last few tool results in full and shorten older ones to what was searched and which units came back.
- **Design**: `02-design.md` §7; decisions D15, D59, D79
- **Libraries**: none new

## Decisions (D15, D59 made concrete)
- New setting `keep_tool_results` (default 3, ≥ 1) in `RunSettings` (T27) and `WorkerDeps`.
- `s.history` stays complete. Only the prompt built in `build_prompt` changes: every `tool` message that holds a tool result (`ToolResult` JSON), except the newest `keep_tool_results` of them, is replaced by a short JSON: `{"shortened": true, "tool": <name>, "args": <arguments>, "category": <category>, "unit_ids": [<unit ids in the result, in order, at most 20>], "note": "Older result shortened; call read_unit to see the text again."}`. The tool name and arguments come from the matching assistant tool call.
- Tool messages that are not tool results (argument errors, quote-verification feedback, `submit_finding` rejections) are kept as they are; they are short.
- The token estimate for the forced last step uses the shortened prompt, so the cap is hit later.
- Prompt files and `prompt_sha256` do not change. Results before and after this task are not comparable; the run's `settings` record `keep_tool_results`.

## Failing tests to write first
1. Six search / read results: the newest 3 are byte-for-byte unchanged, the older 3 are shortened with tool name, args, category and unit ids in order
2. Feedback messages (bad JSON args, quote failures, rejected submission) are never shortened
3. `s.history` is unchanged after building the prompt (only `s.messages` is shortened)
4. A result with more than 20 unit ids keeps the first 20; a result with no unit ids (`not_found`) keeps an empty list
5. `keep_tool_results` larger than the number of results → nothing shortened; `keep_tool_results` < 1 rejected by `RunSettings`
6. Worker with a scripted fake: a long check whose full-history prompt would exceed the token cap now reaches `submit_finding` before the forced step; tokens in are lower than without shortening
7. A shortened result never contains the unit text (the quote cannot be copied from a shortened message)
