## Users and permissions
- `seed.py` (`python -m cda.api.seed`, idempotent): users `sarah` (role `lead`, "Sarah Chen") and `alex` (role `analyst`, "Alex Nguyen"); teams "Energy & Resources" (sarah, alex) and "Financial Services" (sarah only). Sarah sees all packs because she belongs to every team; visibility stays team membership (`cda.tools.permissions.visible_pack_clause`). Compose runs the seed before uvicorn.
- `X-Demo-User: sarah|alex` selects the user; missing or unknown → 401.
- Every query that reads a pack, document, run, finding or event joins visibility; anything not visible is **404** (never reveal existence). Role violations on visible resources are **403**.
- Lead only: create pack, upload, set parts, delete document, index, review. Lead and analyst: read, start runs, cancel runs, export (analyst only on packs he can see).
- Errors are JSON `{"error": "<code>", "message": "<short text>"}`; no stack traces, SQL, paths or secrets.
- Every write adds an `audit_log` row (`actor` = handle, `action`, `target`, small `detail`).

## Routes
**Packs and documents**
- `POST /packs` `{company, reporting_year, team_id}` → 201 (lead; the team must be one the lead belongs to). `GET /packs` → visible packs with document counts. `GET /packs/{id}` → pack, documents (filename, kind, page_count, parts, `index_status`), latest runs.
- `POST /packs/{id}/documents` multipart `file`, `kind` (`annual|sustainability|other`), optional `parts` (JSON list of `{kind, first_pdf_page, last_pdf_page, label}`, validated with `cda.parsing.parts.Part`) → 201. Reject non-PDF (must start with `%PDF-`), files over the size limit (default 50 MB, `CDA_MAX_UPLOAD_MB`) → 413, more than 600 pages or parse errors → 422 with the `ParseError` code (D49), the same sha256 already in the pack → 409. Store the file at `{CDA_UPLOAD_DIR}/{pack_id}/{sha256}.pdf`, then `ingest_pdf` and `replace_parts` in the request (parsing is fast). The document starts with `index_status = "pending"`.
- `PUT /packs/{id}/documents/{doc}/parts` → replace parts (lead). `DELETE /packs/{id}/documents/{doc}` → soft delete (D53, lead). `GET /packs/{id}/documents/{doc}/file` → the PDF (`application/pdf`), for `#page=N` links.
- `POST /packs/{id}/parse` → 202: index every non-deleted document that is not fully indexed (`index_document` with the app's embedder) in a background task, one indexing job per pack at a time (a second call while one runs → 202 with the same state). `index_status`: `done` when every `paragraph`/`table_row` unit has an embedding, `indexing` while the job runs, `failed` if the last job raised (message kept in memory), else `pending`. The app embedder is `BgeEmbedder` warmed up at startup (lifespan), injectable for tests (`create_app(embedder=...)`).

**Runs**
- `POST /runs` `{pack_id, method, model_key, budget_usd}` with header `Idempotency-Key` (1–200 chars; missing → 400) (D24). `method` ∈ `A, B, C` (LC is experiment-only → 422); `model_key` from `config/models.yaml`; `budget_usd` 0 < x ≤ 10, default 2.0. The pack must have ≥ 1 document and every document `done` (else 409 `pack_not_indexed`). Insert `runs` (`queued`, `check_set_version`, `prompt_sha256()`, creating the `check_sets` row if missing), `NOTIFY cda_runs`, 201. Same key and same body → 200 with the existing run; same key, different body → 409.
- `GET /runs/{id}` → status, method, model, budget, spent, tokens, timings, counts by finding status, error.
- `GET /runs/{id}/events` (SSE, D44): honour `Last-Event-ID` (header) or `?last_event_id=`; send stored `run_events` with id > last in order, then `LISTEN run_<id>` and send new rows as they are notified (T14's channel and payload); each message `id: <event id>`, `event: <type>`, `data: <payload JSON>`; heartbeat comment every 15 s; end the stream after `run_final`, `run_failed` or `run_cancelled`.
- `POST /runs/{id}/cancel` → `cancelled` from `queued|running|waiting_review` (T12 then marks the remaining checks `not_checked`); otherwise 409.

**Findings, reviews, export**
- `GET /runs/{id}/findings` → one row per check in `checks.yaml` order: check id and title, status, confidence, `needs_review_reason`, relief, evidence count, review state (`none|reviewed`), version.
- `GET /findings/{id}` → rationale, missing aspects, evidence (quote as **plain text**, D50; verified, role, document filename, part kind/label, pdf_page, printed_page, link `/packs/{pid}/documents/{did}/file#page=N`), facts, inconsistencies that reference the finding, reviews, and a trace: its `llm_calls` (step, tokens, cost, latency) and its `tool_called` events.
- `POST /findings/{id}/reviews` `{decision: "accept"|"change", new_status, note, version}` (lead only): `note` required, 1–2000 chars; `new_status` required for `change` (one of `evidence_found, partial_evidence, no_evidence_found, inconsistent, not_applicable`) and forbidden for `accept`; `version` must equal `findings.version` (optimistic lock) else 409 with the current version. Insert `reviews`, apply the status for `change`, bump `version`, audit log; if the run is `waiting_review` and no unreviewed `needs_review` finding remains, `NOTIFY cda_runs` so the worker resumes it (T14 claim rule).
- `GET /runs/{id}/export?format=md|json|csv` (lead and analyst): header with company, year, method, model, prompt hash, check-set version, `Draft` unless the run is `final`; one row per check with status, relief, evidence (document, pdf page, quote), review note. Markdown escapes `\ ` * _ { } [ ] ( ) # + - . ! | < >` in every model- or document-derived string (D50). CSV: a cell starting with `= + - @`, tab or CR is prefixed with `'` (formula injection). JSON is the plain data.

## Tests to write first (`tests/api/`, httpx `AsyncClient` on the app, testcontainers DB, `HashEmbedder`, tmp upload dir; no model calls)
1. Auth: no header / unknown user → 401; alex cannot see a Financial Services pack (404 on GET, findings, export, SSE).
2. Roles: alex → 403 on create pack, upload, parts, delete, parse, review; 201/200 on start run, cancel, export for his pack.
3. Upload: a small PDF (build with pymupdf in the test) → 201, document parsed, `index_status = pending`; non-PDF → 415 or 422; oversize → 413; duplicate → 409; parts saved and validated (overlap → 422).
4. Index: `POST /parse` → 202; after the background task, `index_status = done`; `POST /runs` before indexing → 409 `pack_not_indexed`.
5. Runs: create → 201 queued with check-set version and prompt hash; `NOTIFY cda_runs` sent (listen in the test); same key+body → 200 same id; same key different body → 409; missing key → 400; method LC → 422; budget 0 or 11 → 422.
6. Cancel from queued → cancelled; cancel a final run → 409.
7. Findings list order and fields; detail with plain-text quotes, links, facts, inconsistencies, trace from `llm_calls` and `tool_called` events (insert rows directly).
8. Review: accept; change with new status; missing note → 422; `new_status` with accept → 422; stale version → 409 with current version; alex → 403; last pending review on a `waiting_review` run sends `NOTIFY cda_runs`; audit rows written.
9. SSE: stored events after `Last-Event-ID` arrive in order; an event emitted with T14's `EventSink` while connected arrives; stream closes after `run_final`.
10. Export: md escapes a quote containing `*`, `|`, `[x](y)` and `<script>`; csv prefixes a cell starting with `=`; json round-trips; `Draft` vs `Final` header.
11. Errors never contain SQL text or file paths (assert on a forced 500 with a patched failing query).
12. Seed is idempotent (run twice → two users, two teams).
