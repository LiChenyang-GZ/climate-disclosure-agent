# T33 · Say which pages have no readable text

- **Model**: — (Claude Code writes it)
- **Tier**: normal
- **Depends on**: T04, T20, U2
- **Goal**: A PDF that has no text at all is rejected (`no_text_layer`), but single scanned or image-only pages pass silently, so nobody is told "these pages were not read" (note 13, items 3 and 49). Show those pages on the pack, in the API and in run exports.
- **Design**: `02-design.md` §5, §11, §11.1; decisions D5, D92
- **Libraries**: none new

## Decisions (D92)
- A page "has no readable text" when no paragraph or table-row unit of the document has that `pdf_page` (for Word / Excel the page is the section / sheet number, X1). It is derived from stored units at query time: no parser change, no migration, so existing packs get it without re-parsing and the parser output stays byte-identical (`cda-parse-4`). A page with only a header or footer (removed as margins) also counts, which is right: nothing on it can be found.
- Shown in: `GET /packs/{id}` documents (`pages_without_text: [int]`, sorted); run export JSON (per document) and Markdown (one line per document that has any: "Pages with no readable text in <file>: 3, 7, 12–14"); the pack detail page (one line under the document, ranges compacted, e.g. "No readable text on PDF pages 3, 7, 12–14").
- The agent's tools do not change in this task (that changes what the model sees; it goes with the design discussion).

## Failing tests to write first
1. A pack whose PDF has a blank page 2 and an image-only page 4 → `pages_without_text == [2, 4]`; a fully text PDF → `[]`
2. A Word document whose second section is empty → `[2]`
3. Markdown export lists the pages as compact ranges per document; JSON has the list; a document with none adds no line
4. A deleted document is not listed
5. Playwright: the pack detail row shows the line when the list is non-empty and nothing when empty
