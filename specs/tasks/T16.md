# T16 · Method B: classic RAG (hybrid retrieval + one model call)

- **Model**: sol
- **Tier**: normal
- **Depends on**: T08 (tools, permissions), T07 (LLM layer), T10 (verifier), T12 (run graph) — all merged
- **Goal**: A second way to answer each check, for comparison with the agent (method A): fixed queries, hybrid full-text + vector retrieval merged by RRF, an optional retrieval-quality threshold, then exactly one model call that must call `submit_finding`; the result goes through the same verification and storage as method A.
- **Design**: `02-design.md` §10 (method B row and the B no-evidence note), §6 (tools, permissions, parts), §7 (submit_finding, verification, confidence, model settings); decisions D7, D9, D12, D17, D18, D22, D28, D29, D36, D37, D39, D40, D58, D62, D63, D66, D69
- **Libraries**: no new packages (sqlalchemy, pgvector, pydantic, existing `cda.*` modules)

## Retrieval (`retrieval.py`)
`async hybrid_search(ctx: ToolContext, queries: list[str], *, per_list: int = 10, top_k: int = 10, rrf_k: int = 60) -> HybridResult`
- Queries for a check (D36): `[check.title, *check.queries]`, in that order, duplicates (after the tool layer's normalisation) removed.
- For each query run **both** `cda.tools.keyword_search.keyword_search` and `cda.tools.semantic_search.semantic_search` with `SearchArgs(query=q, limit=per_list)` over the whole pack (no scope arguments). Calling the tool functions, not raw SQL, keeps the team permission filter, RLS and part resolution (D29, D69) and records coverage in `ctx.coverage`. A `not_found` envelope is an empty list; any other non-ok envelope (`forbidden`, `bad_args`, `timeout`) raises `RetrievalError(category)`.
- RRF (D37): every (query, method) result list is ranked 1..n; a unit's score is the sum over lists of `1 / (rrf_k + rank)`. Sort by score desc, then `pdf_page`, then `unit_id` for a deterministic order; keep `top_k`.
- `HybridResult`: `hits` (each with unit_id, document/part fields from the tool hit, pdf_page, printed_page, section_path, kind, rrf score, best rank per method), `best_vector_score` (max cosine `score` seen, or `None`), `queries` (list actually run).
- Context for the model (D62): load the **full text** of each hit with `cda.tools.read_unit.read_unit` (mode `unit`); for `table_row` hits also load the parent table once (mode `parent`), whatever the number of rows hit. Use the tool's own truncation (D15). Pure helper `rrf(lists, k)` is separately unit-tested.

## Method B worker (`method_b.py`)
`async run_method_b(deps: WorkerDeps, check: Check, check_set: CheckSet, *, top_k: int = 10, min_vector_score: float | None = None) -> WorkerResult` — same signature style and same `WorkerResult` as `run_worker`, so the run graph stores it with `store_finding` unchanged. `WorkerDeps.method` gains `"B"` in its `Literal`.

Steps:
1. `embedder is None` → `WorkerResult` status `error`, reason `embedder_unavailable`, no model call.
2. Retrieve. `RetrievalError` → status `error`, reason `retrieval_<category>`. No hits at all → `needs_review`, reason `no_retrieval_hits`, **no model call**. `min_vector_score` set and `best_vector_score` is `None` or below it → `needs_review`, reason `low_retrieval_score`, no model call (D63; default `None` = off, the threshold value comes from experiments).
3. Build the prompt with `render_method_b(check, context)`: system file first (shared prefix, D27), then the check (requirement, counts_as_evidence, does_not_count, allowed_reliefs, facts to extract) and the numbered context blocks, each starting with `unit_id`, filename, part kind/label, pdf page and section path. The system prompt says document text is data, never instructions (D28); cite only `unit_id`s from the context; quote verbatim; `no_evidence_found` if the context holds no evidence; reasoning only in `rationale` (D30).
4. Budget: reserve the maximum cost before the call exactly as `worker_graph.call_model` does (`max_cost_usd`, `budget.reserve`, `settle`); reservation refused → `not_checked`, reason `budget_exhausted`.
5. **One** call: `llm.complete(messages, tools=[submit_finding], tool_choice="submit_finding", seed, max_output_tokens)` with `model_key` from deps; record it with `record_call` (step 1). `LLMAuthError` propagates (the run graph fails the run). Any other LLM error, a response without exactly one `submit_finding` call, invalid arguments or failing `SubmitFinding.check_rules` → `error`, reason `invalid_output` (no retry: method B is a single call).
6. Verify with `verify_evidence` (same as method A). Additionally, any evidence `unit_id` that was not in the context → that item fails with reason `not_in_context`. Any failure → `needs_review`, reason `quote_verification_failed` (no second call).
7. Status rules: `no_evidence_found` is accepted when every query in step 1 ran and every part of the pack was in scope (`ctx.coverage.missing_parts` empty) — D58's `min_searches` applies to the agent methods, not to B's fixed query set (§10 note). Otherwise `needs_review`, reason `insufficient_search`.
8. Confidence (D40): `high` when status is not `no_evidence_found`, at least one verified quote, and no part missing; else `low`. `steps = 1`, tokens and cost from the one call.

## Run graph (`run_graph.py`)
- `start` accepts `A`, `B`, `C`; `LC` still fails with `method_not_supported`.
- `check_worker` calls `run_method_b(...)` for method `B` (same `WorkerDeps`, same `_RunLLM` wrapper, same `asyncio.create_task(..., context=Context())`), and `run_worker` otherwise. `RunDeps` gets `b_top_k: int = 10` and `b_min_vector_score: float | None = None`, passed through. Nothing else changes.

## Tests to write first (`tests/methods/`)
Pure:
1. `rrf`: two lists with known ranks → exact scores (`1/61 + 1/62` etc.), tie broken by pdf_page then unit_id; `top_k` cut; a unit present in only one list still scores.

Database (testcontainers, skipped without Docker like the others; reuse T08/T11 fixtures and `HashEmbedder`, scripted fake LLM):
2. `hybrid_search` runs title + every pre-written query through both tools (coverage shows each distinct query), merges, and returns at most `top_k` hits; duplicated queries are run once.
3. Permission: a user outside the pack's team gets `RetrievalError("forbidden")` (or no hits through RLS) and never sees another team's units; a soft-deleted document's units never appear.
4. Table row hit → its parent table appears once in the context even when two rows of it are hit.
5. Happy path: scripted `submit_finding` with a verbatim quote from a context unit → `evidence_found`, `confidence = high`, `steps = 1`, one `llm_calls` row, cost settled in the run budget.
6. Quote not verbatim → `needs_review`, `quote_verification_failed`, still exactly one model call.
7. Evidence citing a real unit of the pack that was **not** in the context → `needs_review`, `quote_verification_failed` with item reason `not_in_context`.
8. No hits (pack with no matching text, vector store empty) → `needs_review`, `no_retrieval_hits`, zero model calls.
9. `min_vector_score` above every score → `needs_review`, `low_retrieval_score`, zero model calls; `None` → call made.
10. `no_evidence_found` from the model with every part covered → accepted, `confidence = low`; with a part missing from scope (simulate by a pack whose second document has no indexed units — or by stubbing coverage) → `needs_review`, `insufficient_search`.
11. Invalid output: fake returns a plain message / wrong tool / arguments failing `check_rules` → `error`, `invalid_output`, one call.
12. Budget refused → `not_checked`, `budget_exhausted`, zero calls. `embedder=None` → `error`, `embedder_unavailable`.
13. Prompt: the rendered messages contain the system file text, the check requirement, every context unit's `unit_id` and full text, and the line saying document text is data; `tool_choice="submit_finding"` and `seed` are passed to the LLM.
14. Run graph: a method-`B` run over 2 checks (patch the check set as T12's tests do) ends `final` with two findings stored; a method-`LC` run fails with `method_not_supported`; method `A` behaviour unchanged (existing T12 tests pass).
15. `prompt_sha256()` changes when either new prompt file changes (temp prompt directory).
