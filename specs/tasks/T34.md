# T34 · Stop a run when the model service keeps failing

- **Model**: — (Claude Code writes it)
- **Tier**: normal
- **Depends on**: T12, T14
- **Goal**: Design 11.5 #16 says a run should stop after repeated model failures; the code lets every check retry and fail on its own, so an outage turns all 15 checks into `error` / `llm_unavailable` one by one (note 13, item 28).
- **Design**: `02-design.md` §8; decisions D21, D91
- **Libraries**: none new

## Decisions (D91)
- The run counts checks that end `error` / `llm_unavailable` (retries exhausted) in a row, in the order they finish. Any other result resets the count.
- At 3 in a row the run ends `failed` with error `llm_unavailable` and a `run_failed` event, the same path as `llm_auth` (D21): findings already stored stay, checks not yet finished are not stored, the reserved budget is released as for other failures. The UI and API already show `failed` with the error's message ("The model service is temporarily unavailable").
- Not resumed automatically: the person starts a new run once the service is back. Automatic pause and resume needs a new run status and is left for later.
- The threshold is a constant (3), not a run setting.
