# T27 · Record each run's settings on the run

- **Model**: — (Claude Code writes it)
- **Tier**: normal
- **Depends on**: T12, T18
- **Goal**: a run's step cap, token cap, LC scope and the other knobs live only in `RunDeps` and on the `run_eval` command line, so a stored result cannot say what settings produced it (note 13, items 58–59; design review 11/17). Store them on the run and make the stored values the ones the worker uses.
- **Design**: `02-design.md` §8, §13; decisions D15, D79, D87
- **Libraries**: none new

## Decisions (D87)
- Migration `0010_run_settings`: `runs.settings jsonb NULL`. Existing rows stay NULL ("not recorded"); they are not backfilled with guesses.
- `cda.agent.run_settings.RunSettings` (Pydantic, `extra="forbid"`): `step_cap` (≥ 2), `token_cap` (≥ 1), `max_output_tokens` (≥ 1), `tool_timeout_s` (> 0), `seed` (int or null), `b_top_k` (≥ 1), `b_min_vector_score` (float or null), `lc_scope` (`pack` | `sustainability`), `lc_max_prompt_tokens` (≥ 1). `RunSettings.from_deps(deps)` takes the values from `RunDeps`.
- `run_run` `start`: when `settings` is NULL, write `from_deps(deps)`. The stored values (stored keys over `RunDeps` defaults) are what every check of the run uses, including after a resume. Stored settings that fail validation → run `failed` with error `invalid_settings`.
- `run_eval` writes the settings from its flags on the runs it creates. `score_stored_run` adds `settings` (or null) to each scored run's result. Scoring logic is unchanged.
- API: `GET /runs/{id}` and the MCP `get_run` return `settings` (it is a column). The Markdown export adds a line `**Settings:** step cap 20 · token cap 300,000`, plus `· LC scope: sustainability part only` / `whole pack` for LC runs, or `**Settings:** not recorded` for older runs.

## Failing tests to write first
1. A queued run with NULL settings gets `from_deps` written at start; a second `run_run` (resume) keeps it
2. A run whose stored settings say `step_cap: 2` stops agent checks at 2 steps even though `RunDeps.step_cap` is 20 (stored values win)
3. Stored settings with an unknown key or `step_cap: 1` → run `failed`, `invalid_settings`, no findings
4. `run_eval` (fake LLM, no network) creates runs whose settings carry `--step-cap`, `--token-cap`, `--lc-scope`; the scored result has them
5. Markdown export: settings line for an A run, LC scope wording for an LC run, "not recorded" for NULL
6. Migration upgrades and downgrades; existing rows keep NULL
