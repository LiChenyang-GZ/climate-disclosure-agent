## Behaviour
- **`context_header.py`** (D6): `context_header(filename, section_path) -> str` = `"{filename} > {section_path}"`, or just `filename` when `section_path` is empty. Used for indexing only; never part of `text`, so quotes stay verifiable.
- **`embed.py`** (D10): `Embedder` protocol with `dim: int`, `embed_passages(texts) -> list[list[float]]`, `embed_query(text) -> list[float]`.
  - `BgeEmbedder(model_name="BAAI/bge-small-en-v1.5", device="cpu", batch_size=32)`: loads `SentenceTransformer` lazily on first use (importing the module must not import torch); `normalize_embeddings=True`; queries get the bge v1.5 query prefix `"Represent this sentence for searching relevant passages: "`, passages get none.
  - `HashEmbedder(dim=384)`: deterministic, no model (token hashing into a normalised vector so texts sharing words are closer than unrelated texts). Used by tests here and in later tasks.
- **`index.py`**: `async index_document(conn, document_id, embedder) -> IndexStats`:
  - for every unit of the document with `context_header IS NULL`: set it from `documents.filename` + `section_path`;
  - for `paragraph` and `table_row` units with `embedding IS NULL`: embed `f"{context_header}\n{text}"` (D6, D62; `section` and `table` parents are not embedded);
  - embedding runs in `asyncio.to_thread` in batches; updates use one executemany per batch; only `context_header` and `embedding` are updated (the D52 trigger forbids anything else);
  - idempotent: a second call does nothing and reports 0 updates; `IndexStats(headers_set, embedded)`.
  - Rejects an embedder whose `dim != 384` with `ValueError` before writing.
- **`fts.py`** (D35): `async keyword_units(conn, *, document_ids, query, limit=10) -> list[Hit(unit_id, rank)]`: `websearch_to_tsquery('english', query)`, rank `ts_rank_cd(tsv, q)`, only `paragraph` / `table_row` units of the given, non-deleted documents, ordered by rank desc then `unit_id`; `limit` 1–50 else `ValueError`; a query with no searchable terms (e.g. `"the"`) returns `[]`.
- **`vector.py`**: `async vector_units(conn, *, document_ids, query_embedding, limit=10) -> list[Hit(unit_id, score)]`: cosine distance `embedding <=> :q`, score = `1 - distance`, same unit-kind / document / limit rules, units without an embedding are skipped.
- No permission checks here: callers (T08 tools, T09 RLS) pass only document ids the user may see. State this in the module docstrings.

## Failing tests to write first
No test downloads the real model except the `model`-marked one, which is skipped unless `CDA_RUN_MODEL=1`.
1. `context_header("a.pdf", "Climate > Metrics")` → `"a.pdf > Climate > Metrics"`; empty path → `"a.pdf"`
2. `HashEmbedder`: 384 dims, unit length, deterministic; "scope 1 emissions" is closer to "scope 1 and 2 emissions" than to "board remuneration"
3. Importing `cda.indexing.embed` does not import `torch` (`"torch" not in sys.modules` in a subprocess)
4. `BgeEmbedder.embed_query` adds the query prefix and `embed_passages` does not (stub the `SentenceTransformer` class; assert the texts it receives and `normalize_embeddings=True`)
5. (db) `index_document` on a document with a section, two paragraphs, a table and a table row → headers set on all 5, embeddings only on the 2 paragraphs + 1 row; stats correct
6. (db) second `index_document` call → `IndexStats(0, 0)`, no rows changed
7. (db) after indexing, `units.tsv` includes header terms: a keyword search for the filename stem finds the units
8. (db) `index_document` with a 3-dim embedder → `ValueError`, nothing written
9. (db) `keyword_units`: "scope emissions" ranks a unit mentioning "Scope 1 emissions" twice above one mentioning it once; `section`/`table` units and units of a soft-deleted document or of a document not in `document_ids` never appear; `"the"` → `[]`; `limit=0` and `limit=51` → `ValueError`
10. (db) `vector_units` with `HashEmbedder`: the nearest unit to an embedded query is the one with the same text; unembedded units skipped; same document filtering
11. (`model` marker) `BgeEmbedder` returns 384-dim unit vectors and ranks a relevant passage above an irrelevant one
