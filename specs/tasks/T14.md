# T14 · Worker process: claiming, leases, events

- **Model**: sol
- **Tier**: normal
- **Depends on**: T12
- **Goal**: The long-running worker process: claim one run at a time with `FOR UPDATE SKIP LOCKED`, hold it with a lease renewed every 30 s, run it with T12, resume runs whose reviews are done or whose lease expired, and publish progress as `run_events` rows plus `NOTIFY`.
- **Design**: `02-design.md` §2 (architecture bullets), §8; decisions D23, D43, D44, D45, D65
- **Libraries**: sqlalchemy (asyncpg driver; raw asyncpg connection for LISTEN), no new packages

## Settings (`config.py`)
`worker_id` (default: `f"{hostname}-{pid}"`), `lease_seconds: int = 90`, `heartbeat_seconds: int = 30`, `poll_seconds: float = 5.0`, `notify_channel: str = "cda_runs"`. `database_url` already exists. The OpenAI key is never a setting (the SDK reads its own environment variable).

## Claiming (`claim.py`, D43, D45, D65)
`async claim_next(engine, worker_id, lease_seconds) -> UUID | None`, one transaction:
1. `SELECT pg_advisory_xact_lock(<fixed 64-bit key>)` — serialises claims across worker processes.
2. If any run is `running` with `lease_expires_at > now()` owned by someone else → return `None` (**one run at a time system-wide**, D45).
3. Otherwise pick, `ORDER BY created_at, id LIMIT 1 FOR UPDATE SKIP LOCKED`, the first run that is either
   - `queued`, or
   - `running` with `lease_expires_at` NULL or in the past (crashed worker; it resumes from the checkpoint, D23), or
   - `waiting_review` with no `needs_review` finding lacking a `reviews` row (review finished; resume to `final`).
4. Set `lease_owner = worker_id`, `lease_expires_at = now() + lease_seconds`; commit; return its id.

## Lease (`lease.py`)
`async with hold_lease(engine, run_id, worker_id, lease_seconds, heartbeat_seconds) as lease:` starts a heartbeat task that every `heartbeat_seconds` runs `UPDATE runs SET lease_expires_at = now() + … WHERE id = … AND lease_owner = worker_id` in its own committed transaction. If it updates 0 rows, the lease is lost: `lease.lost` becomes set and the run task is cancelled. On exit: stop the heartbeat and clear `lease_owner` / `lease_expires_at` (only if still the owner). A run left `waiting_review` releases its lease so it can be claimed again after review.

## Events (`events.py`, D44)
`EventSink` for T12: `async emit(run_id, check_id, type, payload)` inserts one `run_events` row in its own short committed transaction and, in the same transaction, `SELECT pg_notify('run_' || replace(run_id::text, '-', ''), <event id as text>)`. Payload JSON must not contain secrets or exception messages (T12 already passes only safe fields).

## Worker loop (`main.py`, `deps.py`)
- `build_run_deps(settings, checkpointer) -> RunDeps`: `OpenAIClient(ModelTable.load())`, `BgeEmbedder()` (lazy; only used by method C), `comparer = cda.compare.compare_run` **if importable, else the no-op** (T13 lands in parallel; use a guarded import), `emit` from `events.py`.
- `async serve(engine, settings, *, deps_factory=build_run_deps, run_fn=run_run, stop: asyncio.Event)`: open the checkpointer once (`open_checkpointer`), `LISTEN` on `notify_channel` with a raw asyncpg connection (the API will `NOTIFY cda_runs` on insert, T20), and loop until `stop` is set: `claim_next`; if a run is claimed → `hold_lease` + `run_fn(engine, run_id, deps=…)`; if not → wait for a notification or `poll_seconds`, whichever comes first.
- `run_fn` raising does not kill the loop: log the exception type only, release the lease, continue (T12 already marks the run `failed`).
- `main()` keeps the sync signature for the container: SIGTERM/SIGINT set `stop`; the current run's lease is released on shutdown so another worker can resume it immediately. On Windows use a selector event loop (`asyncio.SelectorEventLoop(selectors.SelectSelector())`) because psycopg (checkpointer) cannot run on the Proactor loop; elsewhere the default loop.
- Logs: start, claim (run id), finish (run id, status), lost lease, stop. Never log the database URL or any environment variable.

## Tests to write first (all `db` unless noted; use committed data + `TRUNCATE … CASCADE` cleanup like T12's `test_run.py`)
1. `claim_next` picks the oldest `queued` run and sets owner and expiry; a second call while that lease is live returns `None` even if another run is queued (one at a time)
2. Two concurrent `claim_next` calls (`asyncio.gather`, two engines/connections) → exactly one gets a run
3. A `running` run with an expired lease is reclaimed by another worker id; a live one is not
4. A `waiting_review` run is claimed only after every `needs_review` finding has a review
5. `final`, `failed`, `cancelled` runs are never claimed
6. Heartbeat renews `lease_expires_at` (use `heartbeat_seconds` ≈ 0.1); if another worker overwrites `lease_owner`, `lease.lost` is set and the wrapped task is cancelled; on exit the lease fields are cleared only when still owned
7. `emit` inserts `run_events` rows with increasing ids, and a listener connection on `run_<hex>` receives the event id as payload
8. `serve` with an injected `run_fn` processes two queued runs one after the other, then waits; setting `stop` ends it cleanly; a `NOTIFY cda_runs` wakes it before `poll_seconds`
9. `run_fn` raising → loop continues with the next run; lease released
10. End to end: `serve` with the real `run_run`, a scripted fake LLM (reuse T12 test helpers) and `emit` → the run reaches `final` and `run_events` contains `run_started` … `run_final`
11. (no db) `main()` returns 0 when `stop` is set from a signal handler stub; logs contain no `postgresql://` text
