# T24 · Keyword search: any term matches (OR), ranked

- **Model**: sol
- **Tier**: strict
- **Depends on**: T08 (tools), T18/T19 (retrieval eval and CI gate) — merged
- **Goal**: `keyword_search` matches units containing **any** of the query's terms and ranks them with `ts_rank_cd`, instead of requiring every term (`websearch_to_tsquery` ANDs all terms, so the agent's 5–9-word queries returned nothing in the first paid evaluation). Everything else about the tool stays the same.
- **Design**: `02-design.md` §1 (full-text row), §6 (tools); decisions D29, D35, D58, D60, D62, **D77**
- **Libraries**: sqlalchemy, Postgres full-text functions (no new packages)

## Files
Only these may be created or changed:

## Behaviour (D77)
- Build the tsquery from the query's lexemes joined with OR, using the same `english` configuration as `units.tsv`. A safe way: take `plainto_tsquery('english', query)` (which already stems, drops stop words and quotes lexemes), turn its `&` operators into `|`, and cast back to `tsquery` — or build it from `to_tsvector('english', query)`. Never interpolate the raw query into SQL text; it stays a bound parameter.
- Filter `tsv @@ query`, rank `ts_rank_cd(tsv, query)` descending, ties by `seq`, then `id` (unchanged). Snippets, limit (≤ 10), scope (`document_ids`, `part_ids`), permission filter, soft-delete filter, coverage recording and the repeated-query rule are unchanged.
- A query with no lexemes after stop-word removal (e.g. "the and of") returns `not_found` with the usual message, never an SQL error.

## Failure cases — one test each, written first and seen failing
1. A unit containing only one of eight query terms is returned (it was not under AND).
2. Ranking: a unit containing four distinct query terms ranks above a unit containing one of them; equal ranks keep `seq` order.
3. Stop-word-only query → `not_found`, `ok=False`, no exception.
4. Characters that are tsquery operators or quotes in the query text — `'`, `:`, `&`, `|`, `!`, `(`, `)`, `<->`, `*`, `\` — never raise and never change the semantics into negation or prefix search (e.g. `"!climate"` still finds units containing "climate").
5. Hyphenated words: "climate-related" finds units written "climate-related" and "climate related".
6. Stemming: "emissions" finds "emission"; "risks" finds "risk".
7. Scope, permission and soft delete still apply (a matching unit in another team's pack, in a soft-deleted document, or outside `part_ids` is never returned).
8. Repeated identical normalised query is still rejected with `bad_args`.
9. Retrieval eval (DB, `HashEmbedder`, Wattlebrook): keyword-mode Hit@20 is higher than the AND result recorded in `evals/ci_baseline.yaml` (0.143); hybrid Hit@20 is not lower than its baseline minus 0.02.
