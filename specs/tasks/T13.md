# T13 · Inconsistency detection

- **Model**: sol
- **Tier**: normal
- **Depends on**: T11 (and T12's `Comparer` hook, merged)
- **Goal**: After all checks of a run finish, compare the extracted facts in code, record `inconsistencies` and set the affected findings' status — flags for a human, never verdicts.
- **Design**: `02-design.md` §9 (whole section), §5 (Parts), §4 (`facts`, `inconsistencies`); `01-requirements.md` "Inconsistency types"; decisions D41, D42, D69, D74
- **Libraries**: standard library, pydantic, sqlalchemy (no new packages)

## Files
Only these may be created or changed:
- `src/cda/compare/__init__.py`, `normalise.py`, `facts.py`, `inconsistencies.py` (all new)
- `tests/compare/` (new)

## Entry point
`async compare_run(conn: AsyncConnection, run_id: UUID) -> list[UUID]` (returns the inserted `inconsistencies` ids). It matches T12's `Comparer` signature and is plugged in by T14. It runs on the owner connection inside the transaction T12 opens for `compare`, writes nothing else, and is deterministic (same facts → same rows, ordered by type, then check id).

## Facts used (`facts.py`)
Load every `facts` row of the run's findings together with: the finding's `check_id` and `status`, the fact unit's `document_id`, `pdf_page`, and its **logical part** (`part_id`, `part_kind`) resolved at query time with the same rule as `cda.tools.parts_sql` (D69; reuse its `part_id` / `part_kind` expressions). **Only facts whose unit is cited by a `verified = true` evidence row of the same finding are used**; others are ignored.

## Normalisation (`normalise.py`, D42)
- Emissions units: `t`, `tCO2e`, `tCO2-e`, `t CO2e`, `tonnes CO2e` → `tCO2e` ×1; `kt…` ×1,000; `Mt…` ×1,000,000 (case-insensitive, spaces and the hyphen in `CO2-e` ignored).
- Money: `AUD`, `$`, `A$` ×1; with `thousand` / `'000` / `k` ×1,000; `m` / `mn` / `million` ×1,000,000; `bn` / `billion` ×1,000,000,000 → `AUD`.
- Percent: `%`, `percent`, `pct` → `percent`. `degC`, `°C` → `degC`.
- Anything else → `None` (unknown unit; such a fact is never compared as a number).
- `scope`: lower-case, collapsed whitespace; empty → `None`. `year`: as stored (None if missing).
- `reporting_period` (text in `raw`): parse to an `(end_year, end_month)` pair from forms such as `FY2026`, `FY26`, `year ended 30 June 2026`, `1 July 2025 – 30 June 2026`, `2025-07-01 to 2026-06-30`; `FYxx` means the year ending 30 June (Australian convention). Unparseable → `None`.

## Rules (`inconsistencies.py`, D41, D74)
Each rule writes `inconsistencies` rows with `type`, `finding_id` (or NULL for pack-level), and `detail` JSON containing both sides (`fact_id`, `unit_id`, `part_id`, `part_kind`, `pdf_page`, `raw`, normalised value/unit) and a short `reason`. Status changes below bump `findings.version` by 1 and update `updated_at`, and each one writes an `audit_log` row (`actor = "system"`, `action = "status_changed_by_compare"`, `detail` with old/new status and the inconsistency type).

- **T3 restated figures** (checks with `T3` in `inconsistency_types`: M1, M3): facts with the same `name` coming from **different part kinds** (e.g. `sustainability` vs `annual`). If both normalise to the same unit, both have the same non-null `scope` and `year`, and the values differ by more than 1 % of the larger absolute value → row type `T3`, and every finding owning one of the facts gets status `inconsistent` (highest precedence). If the values differ but scope, year or unit is missing/unknown/different → row type `T3` with `detail.comparable = false`, and the owning findings get `needs_review` with `needs_review_reason = "possible_inconsistency"` (never `inconsistent`, §9). Equal within 1 % → nothing.
- **T4 regulatory target missing from targets** (M3): a `safeguard_baseline` fact from an `annual`-kind part, and no `safeguard_baseline` or `emissions_target` fact of M3 from a `sustainability`-kind part → row type `T4`; the M3 finding gets `needs_review`, reason `regulatory_target_missing` (one-sided, so a flag, not `inconsistent`).
- **T5 cross-reference** (A3): for each `cross_reference_target` fact, flag when its `raw` text (a) does not name any document of the pack (case-insensitive match of a filename stem or a part label) or (b) does not name a location (`section`, `page`/`p.`, `note`, `chapter`, `part`, or a number like `4.2`) → row type `T5` per flagged fact; the A3 finding gets `needs_review`, reason `cross_reference_unclear`.
- **T6 reporting period** (pack-level): `reporting_period` facts (any check) from different part kinds whose parsed `(end_year, end_month)` differ → row type `T6` with `finding_id = NULL`; no finding status changes. Unparseable periods are skipped.
- **T1** (A2): a finding the worker submitted as `inconsistent` with `side_a`/`side_b` evidence → row type `T1` (sides from the evidence rows); status stays `inconsistent`.
- **T2** (S4, D74): a finding the worker submitted as `inconsistent` → row type `T2`, and status becomes `needs_review`, reason `t2_flag` (T2 defaults to review, not a verdict).
- Precedence: `inconsistent` overrides every other status except `error` / `not_checked`; `needs_review` from these rules overrides `evidence_found`, `partial_evidence`, `no_evidence_found`; findings already `inconsistent` are not lowered to `needs_review`.

## Tests to write first
Database tests build a run with findings, verified evidence, facts and a document with a sustainability part + rest part, using direct inserts (no LLM).
1. Normalisation table: each emissions, money, percent and temperature form above → canonical unit and factor; unknown unit → None (parametrised)
2. Reporting periods: each listed form → `(end_year, end_month)`; `FY26` → (2026, 6); garbage → None
3. T3: `scope1_emissions` 1,204 tCO2e (sustainability) vs 1.30 kt (annual), same scope and year → `inconsistent`, one `T3` row with both sides; 1,204 t vs 1.2 kt (within 1 %) → nothing
4. T3 with different `scope` (group vs Australian operations), or missing `year`, or unknown unit → `needs_review`, `possible_inconsistency`, `detail.comparable = false`
5. T3 ignores facts from the same part kind, and facts whose unit has no verified evidence
6. T4: annual-part `safeguard_baseline` and no sustainability-part target → M3 `needs_review`, `regulatory_target_missing`; with a sustainability-part `emissions_target` → nothing
7. T5: reference naming an existing document and a section → nothing; naming no known document → flagged; naming a document but no location → flagged
8. T6: `FY2026` vs `year ended 30 June 2025` across parts → one pack-level `T6` row, `finding_id` NULL, no status change; same period written differently → nothing
9. T1 stays `inconsistent` with a `T1` row; T2 `inconsistent` → `needs_review`, `t2_flag`, `T2` row
10. Precedence: an `evidence_found` M1 finding becomes `inconsistent`; an `error` finding is never changed; an `inconsistent` finding is not lowered by a T4/T5 rule
11. Every status change bumps `version`, writes one `audit_log` row; a second `compare_run` call on the same run inserts no duplicate rows (it first deletes the run's previous `inconsistencies` rows and only re-applies status changes that are still needed)
12. Plugged into T12: a run graph test with `comparer=compare_run` and two scripted M1 facts that disagree ends `inconsistent` for M1 (reuse T12's test helpers by importing them)
