# T21 · Langfuse tracing (exported from the database)

- **Model**: sol
- **Tier**: normal
- **Depends on**: T11–T14 (llm_calls, run_events, worker) — merged
- **Goal**: Optional, self-hosted Langfuse traces of every run (D25): one trace per run, a span per check, a generation per model call, a span per agent tool call — built **after** the run stops, from rows we already store (`runs`, `findings`, `llm_calls`, `run_events`), so tracing never sits on the hot path, never changes run behaviour, and can be re-sent idempotently.
- **Design**: `02-design.md` §1 (tracing row), §2, §4 (`llm_calls`, `run_events`); decisions D25, D44, D66, D78
- **Libraries**: `langfuse>=2.60,<3` (Python SDK v2; matches the self-hosted server image `langfuse/langfuse:2`). Pin both; do not use SDK v3 (it needs a v3 server with ClickHouse, Redis and MinIO).

## Behaviour
- `settings.py`: read `LANGFUSE_HOST`, `LANGFUSE_PUBLIC_KEY`, `LANGFUSE_SECRET_KEY` from the environment; tracing is **off** unless all three are set. Never log or print the keys.
- `export.py`: `async export_run(engine, run_id, client) -> ExportSummary` where `client` is a small protocol (`trace`, `span`, `generation`, `flush`) implemented by a thin adapter over the Langfuse SDK and by a fake in tests.
  - Trace: `id = run_id`, name `run <method> <company> <year>`, metadata: method, model key and model name, check-set version, prompt hash, budget, spent, status, error, timings; tags: method, model key.
  - Span per check: `id = finding_id` (or a deterministic UUIDv5 of run id + check id when no finding exists), name = check id, start/end from that check's `check_started` / `check_finished` events, output: status, confidence, needs_review_reason, steps, tokens, cost, rationale (model text). No document quotes.
  - Generation per `llm_calls` row, parented to its check span: `id = llm_call.id`, model, `usage` input/output (and cached as metadata), cost, `end_time = created_at`, `start_time = created_at − latency_ms`, metadata: step, prompt and tools hashes, reasoning effort from `config/models.yaml`. Prompt text is not stored by us and is not sent.
  - Span per `tool_called` event, parented to its check span: name = tool, input = query and part ids, output = category and hit count, time = event `created_at`.
  - Run-level events (`run_started`, `run_failed`, `run_final`, ...) as trace events or metadata.
  - Idempotent: the same run exported twice produces the same ids (Langfuse upserts by id), so a run resumed after review is re-exported in place.
- Worker (`runner/main.py`): after `run_fn` returns (any status) and tracing is on, `await export_run(...)` and flush; any exception is logged as `trace export failed <ExceptionType>` and swallowed — tracing never fails or delays a run's own work.
- CLI: `python -m cda.tracing.export --run <id>` (needs `DATABASE_URL` and the Langfuse variables) for re-sending an old run.
- `docker-compose.langfuse.yml`: services `langfuse` (`langfuse/langfuse:2`, port `127.0.0.1:3000`) and `langfuse-db` (`postgres:16`, its own volume); fixed local-only secrets for `NEXTAUTH_SECRET` / `SALT`; `LANGFUSE_INIT_*` variables (if supported by the pinned image) to create a local project and keys `pk-lf-local` / `sk-lf-local`; and it passes the three Langfuse variables to the existing `worker` service. Document in a comment at the top how to start it and where to open the UI.

## Tests to write first (`tests/tracing/`, fake client, testcontainers DB; no network)
1. Settings: tracing off when any variable is missing; on when all three are set; keys never appear in `repr` or logs.
2. Export of a run built with direct inserts (2 checks, 3 `llm_calls`, 2 `tool_called` events, run events): one trace with the run id and metadata; two check spans with the right start/end, status and tokens; three generations with usage, cost, times and parents; two tool spans with query, part ids and hits.
3. A check without a finding (cancelled run) still gets a span with the deterministic id.
4. Idempotency: exporting twice sends identical ids and payloads.
5. No document quotes and no prompt text in anything sent (insert a finding with evidence quote "SECRET QUOTE" and assert it never appears in the fake client's calls).
6. Worker hook: with tracing on, a run processed by `serve` (fake `run_fn`) is exported once; an exporter that raises is logged and swallowed, and the worker continues to the next run; with tracing off the exporter is never called.
7. The SDK adapter maps protocol calls to the Langfuse v2 client (mock the SDK object; no network).
