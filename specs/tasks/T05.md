# T05 · PDF tables

- **Model**: sol
- **Tier**: normal
- **Depends on**: T04
- **Goal**: Detect tables with PyMuPDF and store each as a `table` parent unit (Markdown) with one `table_row` child per row whose text carries the header cells, so a search hit on one row can be read with its whole table.
- **Design**: `02-design.md` §5 (child units, tables); decisions D33, D62, plus D31, D52, D70 as already implemented in T04
- **Libraries**: pymupdf (`Page.find_tables`), already present

## Behaviour
1. **Detection**: `page.find_tables()` with PyMuPDF's default strategy, inside the existing per-page timing (D49). A detected table with fewer than 2 rows or fewer than 2 columns is ignored (its text stays as ordinary blocks).
2. **Data**: `TableData(header: list[str], rows: list[list[str]], bbox)`. Header = `table.header.names` when PyMuPDF finds a header; otherwise `Column 1`, `Column 2`, …. Cells: `None` → `""`; cell text normalised with `units.normalize_text`. Rows whose cells are all empty are dropped.
3. **Covered text**: a text block whose area lies ≥ 50 % inside a table bbox is removed, so table text is not stored twice.
4. **Placement**: the table becomes one `Block` (bbox = table bbox, `text` = Markdown, `table` = the `TableData`) and goes through the T04 spread / column / reading-order code like any other block, so it gets the right `page_half` and position. Tables are never treated as headings, header/footer or printed page numbers.
5. **Units**:
   - `table` unit: `text` = GitHub Markdown table (header row, `---` separator, one line per row; `|` in a cell escaped as `\|`); parent = innermost section; `section_path` as for paragraphs; `token_count` of the Markdown.
   - one `table_row` unit per data row, parent = the `table` unit: `text` = `"{header}: {cell}"` pairs joined with `"; "`, skipping empty cells (e.g. `Metric: Scope 1 emissions; FY2026: 1,204; FY2025: 1,310; Unit: tCO2e`). Rows are not split even if over 350 tokens.
   - Both carry the page's `pdf_page`, `page_half`, `printed_page`.
6. A table that continues on the next page is two separate tables (no merging across pages).

## Failing tests to write first
Tests generate PDFs with PyMuPDF (draw grid lines with `page.draw_line` / `draw_rect` and insert cell text), no binary fixtures.
1. A 3×4 ruled table with a header row → one `table` unit with the exact Markdown and 3 `table_row` units with the exact `header: cell` text, in row order
2. The table's cell text does not also appear as `paragraph` units; a paragraph above and below the table stays, and the order is paragraph, table, rows, paragraph
3. `table_row.parent_key` is the table; the table's parent is the innermost section and `section_path` matches
4. Empty cells are skipped in row text and kept as empty cells in Markdown; an all-empty row is dropped; `|` in a cell is escaped in Markdown
5. A table without a detected header → `Column 1`, `Column 2`, … labels
6. A 1-row or 1-column "table" → ignored; its text comes out as paragraphs
7. A table on the right half of a spread → `page_half = "right"` on the table and its rows
8. Same table on pages 1 and 2 → two `table` units with their own rows, not merged
9. `ingest_pdf` (db) on a PDF with a table stores `table` and `table_row` units with correct `parent_id`s
10. The T04 golden test (no tables) still produces the same units; `parser_version` starts with `cda-parse-2/`
