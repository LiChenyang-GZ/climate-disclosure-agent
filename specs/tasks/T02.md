## Conventions
- Primary keys: `uuid`, server default `gen_random_uuid()`; except `run_events.id` (`bigserial`, used as SSE event id, D44) and `audit_log.id` (`bigserial`).
- Timestamps: `timestamptz`, server default `now()`.
- Money: `numeric(12,6)` USD. Token counts: `integer`, default 0.
- Allowed values are `text` columns with a named `CHECK` constraint (`ck_<table>_<column>`), not Postgres enum types (easier to extend in later migrations).
- Foreign keys: `ON DELETE RESTRICT` everywhere (nothing is hard-deleted; D53), except `team_members`, `run_events`, `evidence`, `facts`, `llm_calls` which `CASCADE` from their parent.
- Every foreign key column has an index.

## Units are immutable (D52)
A trigger `units_immutable` (BEFORE UPDATE on `units`) raises an exception if any of `document_id`, `parent_id`, `kind`, `pdf_page`, `printed_page`, `section_path`, `text`, `token_count`, `parser_version` changes. Updating `context_header` and `embedding` is allowed (indexing fills them after parsing). Downgrade drops the trigger and its function.

## Model ↔ migration consistency
The SQLAlchemy models must describe exactly what the migration creates (types, nullability, constraints names, indexes, the generated `tsv` column via `Computed`). One test proves it with `alembic.autogenerate.compare_metadata` → empty diff (ignore the trigger, which autogenerate does not track).

## Failing tests to write first (all `db`-marked, using the `pg_url` fixture from T01)
1. `upgrade head` creates all 16 tables; `downgrade 0001_enable_pgvector` removes them and leaves `vector` installed; `upgrade head` again works
2. `compare_metadata` between models and the migrated database → no differences
3. Inserting a `runs` row with `status='done'` → `IntegrityError` naming `ck_runs_status` (do the same for `documents.kind`, `units.kind`, `findings.status`, `evidence.role`, `inconsistencies.type`)
4. Two runs with the same `idempotency_key` → `IntegrityError`
5. Two findings with the same (`run_id`, `check_id`) → `IntegrityError`
6. Same document `sha256` twice in one pack → error; after soft-deleting the first (`deleted_at = now()`), inserting it again succeeds
7. Updating a unit's `text` → error from the trigger; updating its `embedding` and `context_header` → succeeds
8. `units.tsv` is populated on insert; `tsv @@ plainto_tsquery('english', 'scope emissions')` finds a unit whose text mentions "Scope 1 emissions"; changing `context_header` updates `tsv`
9. `embedding` with 3 dimensions → error; 384 dimensions → ok
10. Review with `decision='change_status'`, `new_status='partial_evidence'`, `note='too short'` → error; with a 10+ character note → ok; `decision='confirm'` with a `new_status` → error
11. `run_events.id` increases in insert order for one run
12. Deleting a pack that has documents → error (RESTRICT); deleting a run cascades to its `run_events` and `llm_calls`
