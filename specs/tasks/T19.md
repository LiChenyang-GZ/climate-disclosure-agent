# T19 · CI retrieval gate on the synthetic company

- **Model**: sol
- **Tier**: normal
- **Depends on**: T18 (evaluation harness, merged)
- **Goal**: Every push runs, with no model calls, a retrieval evaluation on Wattlebrook and fails when retrieval quality drops below the committed baseline; it also warns when the prompts changed since the last paid evaluation (D26). CI already runs ruff, mypy and pytest with Docker (D56); this task adds the gate command and fixes two report issues found in T18's review. The workflow step itself is added by the reviewer (`.github/` is protected for Codex).
- **Design**: `02-design.md` §13 (CI bullet, D56, D72), §14; decisions D26, D48, D56, D64, D72
- **Libraries**: no new packages (testcontainers and alembic are already dev/runtime dependencies)

## Gate command (`eval/ci_gate.py`)
`uv run python -m cda.eval.ci_gate [--database-url URL] [--summary PATH] [--update-baseline]`
1. Database: use `--database-url` if given; otherwise start a throwaway `PostgresContainer("pgvector/pgvector:pg16", driver="asyncpg")` (as `tests/conftest.py` does, `127.0.0.1` host) and run `alembic upgrade head` against it. Stop the container at the end, also on failure.
2. Ingest `data/synthetic/wattlebrook` with `ingest_pack(..., embedder=HashEmbedder())` and run `evaluate_retrieval` for `keyword`, `vector` and `hybrid` (same code as `run_eval --retrieval-only`). No LLM client is created; the command must work with no OpenAI key in the environment.
3. Compare with `evals/ci_baseline.yaml`:
   ```yaml
   pack: data/synthetic/wattlebrook
   key_version: 1
   embedder: hash
   tolerance: 0.02          # allowed drop per metric
   metrics:                 # overall, per mode
     hybrid:  {hit_at_1: ..., hit_at_5: ..., hit_at_10: ..., hit_at_20: ..., mrr: ...}
     keyword: {...}
     vector:  {...}
   last_paid_eval:          # filled by hand after a manual paid eval
     prompt_sha256: null
     date: null
     results: null          # path or note
   ```
   Fail (exit code 1) when any listed metric is more than `tolerance` below its baseline value; print each failing metric with baseline and actual. When a metric is more than `tolerance` **above** baseline, pass but print a notice to run with `--update-baseline`. A missing or malformed baseline, or a baseline whose `key_version` differs from the pack's answer key, is an error (exit 2).
4. Prompt guard (D26): if `last_paid_eval.prompt_sha256` is null or differs from `cda.agent.prompts.prompt_sha256()`, pass but print a warning: prompts changed since the last paid evaluation; run `run_eval` manually before relying on new prompt behaviour. Never fails the build.
5. `--summary PATH`: append a Markdown section (the retrieval table from `render_report`, the comparison table baseline / actual / delta / status, and the prompt-guard line) to PATH — CI passes `$GITHUB_STEP_SUMMARY`.
6. `--update-baseline`: write the actual metrics into `evals/ci_baseline.yaml` (keep `tolerance` and `last_paid_eval` as they are), then exit 0.
7. Deterministic: the same commit gives identical numbers (hash embedder, FTS, fixed ordering); runtime under about 60 s.

Create the committed `evals/ci_baseline.yaml` by running `--update-baseline` once after implementation.

## Tests to write first (`tests/eval/test_ci_gate.py`)
Pure:
1. Comparison: equal → pass; one metric 0.03 below with tolerance 0.02 → fail listing that metric; 0.01 below → pass; 0.05 above → pass with the update notice.
2. Baseline file: missing → exit 2; wrong `key_version` → exit 2; unknown mode or metric name → exit 2.
3. Prompt guard: null or different hash → warning text, exit unaffected; same hash → no warning.
4. `--update-baseline` rewrites metrics and preserves `tolerance` and `last_paid_eval` (tmp copy of the file).
5. Summary: appended Markdown contains the retrieval table, the comparison rows and the prompt-guard line; appending twice keeps both sections.
6. Report fixes: a retrieval-only `results` renders without the method table and with the new HashEmbedder sentence (golden file); a full-run report is byte-identical to T18's golden file.

Database (skipped without Docker):
7. `ci_gate` with `--database-url` from the `pg_url` fixture on the committed baseline exits 0, creates no LLM client (patch `OpenAIClient` to raise if constructed), and reports the same numbers on a second run (determinism).
